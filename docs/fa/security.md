# راهنمای امنیت CYBRIX

## اصول رعایت‌شده در کد
- توکن‌ها فقط در **Cloudflare Secrets** (`secret_text` binding) — هرگز در متغیرهای معمولی، کد، لاگ یا مخزن.
- `secrets.local.env` در `.gitignore`؛ `.env.example` بدون مقدار واقعی.
- Webhook تلگرام با `secret_token` — درخواست بدون هدر درست → **403** (تست شد).
- Idempotency آپدیت‌ها با `webhook_events` (پردازش دوباره teleگرام بی‌اثر است — تست شد).
- همه کوئری‌های D1 پارامتری (ضد SQL Injection)؛ خروجی‌ها escape (ضد XSS)؛ CSP + nosniff + DENY فریم در پنل.
- جداسازی داده: غیر-owner فقط داده خودش را در پنل می‌بیند (subquery-scoped).
- خرج اعتبار اتمیک با `batch` و شرط موجودی — مسابقه شرط (race) بسته می‌شود.
- Audit Events برای عملیات حساس (publish، spend، grant، login، خطاها) — بدون توکن.

## حد و مرزهای صادقانه (مهم)
- مبهم‌سازی کد **رمزنگاری نیست**. اگر مشتری به حساب Cloudflare خودش دسترسی دارد، هیچ راهی ۱۰۰٪ جلوی دستکاری را نمی‌گیرد؛ برای سیاست‌های واقعاً تحت کنترل CYBRIX، سرویس سیاست‌گذاری احراز هویت‌شده در نقشه راه است.
- «انسان‌بودن» چند حساب تلگرام با قطعیت قابل تشخیص نیست؛ کنترل‌های فنی (یکتایی ID، عضویت، نرخ، ریسک) اجرا می‌شوند و محدودیت باقی اعلام می‌گردد.
- رویداد ترک‌کردن کانال به‌صورت قطعی از تلگرام نمی‌رسد؛ سیستم در پایان چالش دوباره بررسی می‌کند.

## چرخش توکن‌ها (بعد از تحویل)
1. BotFather → `/mybots` → API Token → Revoke (هر دو بات) → آپدیت `secrets.local.env` + اجرای دوباره `bun scripts/deploy.ts`
2. GitHub → Settings → Developer settings → PAT → Regenerate
3. Cloudflare → My Profile → API Tokens → Roll
4. اگر توکنی جایی عمومی دیده شد: فوراً Revoke کنید و از ادامه استفاده از آن خودداری کنید.

## نصب‌کننده (Builder)
- توکن‌های مشتری فقط در حین نصب در `wizard_state` می‌مانند و **بعد از نصب پاک می‌شوند**.
- حداقل دسترسی توصیه‌شده توکن Cloudflare مشتری: Workers Scripts Edit + D1 Edit + Accounts Read.
- توکن‌ها هرگز در پیام/لاگ کامل نمایش داده نمی‌شوند (ماسک: ۶ کاراکتر اول).
